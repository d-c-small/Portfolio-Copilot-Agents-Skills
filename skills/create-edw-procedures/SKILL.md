# CREATE Stored Procedures Skill

This skill guides you through generating a CREATE schema stored procedure for the EDW (Enterprise Data Warehouse) Silver layer. CREATE procedures handle one-time table creation and population from raw source data.

## When to Use This Skill

Use this skill when:
- The user enters the phrase "Build a CREATE schema stored procedure"
- Creating a new EDW table for the first time
- Building a procedure to perform an initial full data load from raw to Silver
- You need to follow the naming pattern: `create.[org]_[subject]_[SourceSystem]_[Entity]`

**Do NOT use this skill for:** Incremental updates or MERGE operations (use the [`merge-edw-procedures`](../merge-edw-procedures/SKILL.md) skill for those)

### ⚠️ Critical Requirement: Always Consult Template and Example

> **When generating a CREATE schema stored procedure, you MUST refer to both the template and working example.** Do not generate a procedure from scratch without consulting these resources.

## Naming Convention

**Pattern:** `create.[org]_[subject]_[SourceSystem]_[Entity]`

**Examples:**
- `create.hq_fieldops_ProjectHub_Completion`
- `create.sub_finance_AcctVision_Account`

**Components:**
- `[org]` - Organization abbreviation (hq, sub, corp)
- `[subject]` - Subject domain (fieldops, finance, sales, compliance)
- `[SourceSystem]` - Source system name (ProjectHub, SalesPro, FinanceOne)
- `[Entity]` - Specific entity being loaded (Completion, Account, Budget)

## Required Components

Every CREATE procedure must include all of these elements in this exact order:

### 1. Header and SET Options

```sql
-- =============================================================================
-- Procedure: [create].[org]_[subject]_[SourceSystem]_[Entity]
-- Description: Initial creation and population of [Entity] table from raw to EDW
-- Generated by: [AI Agent Name] (e.g., SQL Architect Agent)
-- Created: [Date]
-- Reviewed By: [User Name or Account]
-- Modified: [Date] [User Name or Account] - [Description of changes]
-- WARNING: Review carefully before deploying to production
-- =============================================================================
```

**SET options:**
```sql
SET NOCOUNT ON;
```

### 2. Table Structure, Transformation, and Insert

1. **DROP TABLE IF EXISTS** - Clean state before recreating
2. **CREATE TABLE** - Define all columns with Primary Key, Data columns, LoadHash (VARBINARY(32)), LoadDateTime (DATETIME2(7)), UpdateDateTime (DATETIME2(7) NULL)
3. **CTE transformation** - Use `_[SourceSystem][Entity]` CTE with HASHBYTES calculation
4. **INSERT statement** - Must use comment: "Insert transformed data into the target table"

**Hash format:** `HASHBYTES('SHA2_256', CONCAT_WS('|', ISNULL(CAST(col AS VARCHAR(8000)), '.'), ...))`

## Validation Checklist

- [ ] Header comment block complete
- [ ] SET NOCOUNT ON present
- [ ] DROP TABLE IF EXISTS statement exists
- [ ] CREATE TABLE with proper schema and primary key
- [ ] LoadHash column is VARBINARY(32)
- [ ] LoadDateTime column is DATETIME2(7)
- [ ] UpdateDateTime column is DATETIME2(7) NULL
- [ ] CTE named `_[SourceSystem][Entity]`
- [ ] All relevant columns included in HASHBYTES calculation
- [ ] Hash uses CONCAT_WS with '.' as null placeholder
- [ ] "Insert transformed data into the target table" comment present
- [ ] INSERT statement lists all columns explicitly
- [ ] SELECT statement matches INSERT column order
- [ ] All database references explicit
- [ ] Procedure naming follows pattern

**❌ If ANY item is unchecked, revise the procedure before deployment.**

## Best Practices

1. **Always drop and recreate** - Use DROP TABLE IF EXISTS to ensure clean state
2. **Transform in CTE** - Keep transformation logic in a single, readable CTE
3. **Name CTEs consistently** - Always use `_[SourceSystem][Entity]`
4. **Include all monitored columns in hash** - Think ahead about what MERGE will need to detect
5. **Use explicit column lists** - Never use SELECT *
6. **Cast DATE columns to DATE** - Explicit cast ensures consistent date handling
7. **Set LoadDateTime once** - Calculate GETDATE() at CTE level, not per row
